# 上传前同意护栏（Upload Consent Guard）

**核心规则：涉及把内容上传/发送/发布/共享到「外部且非本人所有」的账户或空间时，禁止静默执行——必须先说明、先警示、先询问，得到用户明确同意后才能继续。**

## 1. 适用范围（触发条件）

只要符合以下任一情形，本规则生效：

- 上传/发送**本机文件、图片、视频/帧、文档、数据、文本**到：
  - 他人的个人账户（社交、网盘、邮箱、云服务、聊天工具等）；
  - 共享/团队/公司账户（非用户个人所有）；
  - 借用或复用的他人登录态（例如驱动“已登录他人/共享账号”的浏览器自动化，向该账号所在服务上传内容）；
  - 用户身份不明确、无法确认归属的外部空间。
- 把内容**发布/提交到非用户所有的远程仓库**（向他人仓库提 PR、向他人仓库推送分支、在他人组织的 CI/工单里贴内容等）。
- 通过**非用户本人的账号**发送消息、评论、帖子、通知。
- 将**用户内容发送到第三方云端视觉/媒体服务**且该服务的账号/数据空间非用户本人所有（例如借用他人 API 额度、他人账号的免费通道）。

不在范围内（正常执行，但仍保持透明）：
- 仅在本机内部处理（如本地 OCR、本地像素分析、本地 ffmpeg 抽帧、L0 本地视频信息层）；
- 上传到**用户本人所有**的账户/服务（用户自己的 GitHub、自己的 API key 所属账号、自己的网盘）。

## 2. 执行前协议（无论触发与否，涉及云端上传先自检）

在**任何**把内容送往外部的动作之前，先完成以下自检（“上传预检”）：

1. **去向**：目的地是哪个服务/账号？该账号**是否确为用户的本人账户**？
   - 是 → 可继续，但属云端传输的，先给用户一句话提示（传什么、去哪）。
   - 否 / 不清楚 → 进入第 3 节流程，**停下询问**。
2. **载荷清单**：要发送的具体内容（文件名/类型/大小/是否含敏感信息：密钥、个人数据、文档正文、未公开代码、图片视频本体）。
3. **可见范围**：接收方、受众、是否公开、是否会留档（记录/日志/训练）。
4. **本地替代**：是否可只在本地完成（本地 OCR / 本地模型 / 先摘要再发文本）？能本地就不外发。

## 3. 触发时的强制流程

遇到第 1 节情形时，**先停手**，按以下顺序执行：

1. 向用户清晰说明（一段话内讲全）：
   - 将上传/发送**什么**（具体文件/内容清单）；
   - 发往**哪个目的地、哪个账号**（含“此账号是否属于您本人”的判断依据，若不确定要明说）；
   - 为什么需要这样做；
   - 谁会看到、是否会公开/留档。
2. 明示风险提示，例如：“这将把内容发送到 **XXX（非您本人的账号/第三方服务）**，可能造成数据泄露或无法撤回。”
3. 询问并获得**用户明确同意**（等待用户亲自回复确认，如“可以”“同意”“继续”）。
4. 仅在收到确认后执行；执行时如发现与描述不符，立即停止并重新询问。

用户拒绝、要求修改内容、或态度不明确时：**不得执行**，改走本地方案或等待进一步指示。

## 4. 禁止事项

- 未经询问就把内容静默上传到非本人账号/第三方非本人空间；
- 借用或复用的他人登录态被用于上传任何用户内容而不事先说明（浏览器自动化、网页端 API 等）；
- 用“只是发一下/没什么影响/对方是熟人”之类的判断代替询问；
- 把一次同意当作永久的、全类型的授权（每次不同目的地/内容都需重新确认）；
- 在用户未确认的情况下将视频帧、图片、文档等发送到外部视觉/媒体 API。

## 5. 与权限系统的关系

本规则是**额外的人机护栏**，不替代、也不被现有的审批/沙箱权限体系取代。即使某个动作在技术上被系统允许（例如已有 API key、已有沙箱写权限），只要落入第 1 节范围，仍然必须先询问。
